# Architecture

- `GamepadQuickMenu.lua` renders an independent eight-slot wheel using native radial segment templates, artwork, and geometry, with a -312 horizontal offset mirroring the native right-hand wheel’s +312 offset. It stays out of `UISpecialFrames` and `UIPanelWindows` so fullscreen-menu discovery does not reposition it or attach chrome; temporary Escape bindings close both normal and binding-picker modes. It reads the native focus manager, binding stack, and effective Share binding to install an addon-owned override at an empty action binding, the unused `TOGGLEUIFOCUS` fallback, the collapsed raid-controls expansion binding, or the supported native Bind screen. The raid fallback is recognized by the top Share-owning binding set’s exact group name and native expansion function, rather than the shared native function-binding CLICK button. Expanded raid controls retain priority. Native focus and binding functions remain intact. Bind entry and exit are discovered by the existing refresh loop without installing hooks on inherited methods of the native edit-frame instance. A periodic check releases the override when interfaces take priority without native focus-manager or radial-show hooks. Share down opens the normal wheel and arms its secure action button; Share up samples the physical right stick and activates the selected preconfigured action in or out of combat. Both edges route to the same button. Cancellation, hiding, or the binding picker prevent release activation; the native Bind-menu Share route opens its picker on press and assigns on release, without activating the slot. A native constant state driver samples physical right-stick input at the manager's roughly 0.2-second cadence, clearing its own state attribute after each sample so the next native update runs again. Its guarded nil transition does no work. The secure sampler retains the selected slot in an owner attribute and calls a visual-only method to paint the same selection. Normal stick callbacks only consume camera input; binding-picker callbacks select assignment slots. Share release samples again and uses the retained secure selection when centered, identically in and out of combat. No insecure selection callback writes protected frame IDs or action attributes. Secure show/hide and combat handlers own Share, cancel, and wheel visibility. X is consumed without activation or slot assignment. Secure visibility wrappers on registered native panels, popups, radial menus, and native chat-focus footers update addon-owned blocker flags and release Share when those interfaces appear. No protected proxy children are added to native panels. The permanently visible collapsed raid-manager tab maps to its `displayFrame`, so only expanded controls block combat opening. Chat windows and edit boxes encountered through any discovery path map to their native focus footer, because idle IM inputs and ordinary chat windows remain visible. Newly available blockers are discovered outside combat. Combat closes the binding picker and restores saved slot actions; slot changes wait until combat ends. The normal wheel footer uses `InputPromptOneIconWithTextTemplate` with `GAMEPAD_FACE_LEFT` and Remove, dimmed in combat. Square removes the securely highlighted custom slot outside combat and disarms activation until Share release closes the wheel. A visual-only unprotected child inside the native bottom prompt container uses plain textures and a font string, without native prompt templates or icon-manager callbacks. Polling computes bounds from native prompt positions and extends the container background for the extra hint, restoring native dimensions when the hint hides. It never joins native prompt or binding tables, invokes native layout, or hooks inherited legend methods. The Share override extends the native `BIND_ACTION` screen by reading its item/spell/macro pickup metadata, without invoking pickup or modifying native binding tables. The elevated binding picker consumes gamepad button events before the native action-bar assignment listener; the initial Share release assigns the retained selected slot and returns to the unchanged native selection. The picker preserves the Share override to the same opener button through release; raw edit listeners pass Share through so the secure post-click assigns and closes without relying on a listener enabled midway through the hold. Circle or an unselected Share release cancels. Square removal is limited to the normal wheel outside combat. Native selection changes dismiss a stale picker. Standalone edit mode and its slash command, cursor assignment, and right-click removal paths are removed; assignment uses native Bind. Character SavedVariables persist entries. Macro entries retain scope, name, and body to resolve indices after reordering; uniquely named edits remain usable, while missing or ambiguous matches have no secure action. `UPDATE_MACROS` refreshes macro icons and secure attributes outside combat.

- Quick-wheel sector 3 (top) is a runtime-only quest entry resolved from `C_SuperTrack.GetSuperTrackedQuestID`, watch membership, and `GetQuestLogSpecialItemInfo`, with the tracker’s completed-quest item visibility rule. Protected action refreshes and artwork update together outside combat on quest/log/watch events. All presentation and action reads use the runtime slot resolver; assignment and removal reject the reserved slot. Slot 7 (bottom) is reserved for Leave Party and marks an addon-owned leave request. Armed Share release closes the wheel before calling `ForeverTweaksLeaveGroupRequest.LeaveParty` through the secure handler’s `CallMethod`; it does not delegate a synthetic button click. Share release copies spell/item/macro attributes for ordinary actions. Leave is disabled while solo, with a live group check before leaving. Both reserved slots reject binding/removal; their saved entries relocate to one of six custom slots or remain saved until space opens. Quest-item cooldowns use the quest’s current log index.

- Quick-wheel slot buttons own native cooldown widgets with the standard dark swipe fill and countdown text centered over their icons. The visible-wheel refresh reads rankless spell cooldowns, item cooldowns, or the resolved macro spell/item and passes spell duration objects to `SetCooldownFromDurationObject`, keeping restricted timing inside the native widget; item times use `SetCooldown` without timer arithmetic. Empty or unresolved slots clear their countdowns.

- `ActionCooldowns.lua` sets the native countdown abbreviation threshold to zero on action-button cooldown widgets, disabling M:SS formatting. It initializes registered buttons at login and post-hooks the shared `ActionButton_ApplyCooldown` path for controller buttons and dynamically created flyouts. Normal, charge, and loss-of-control widgets retain native timing and visibility; no cooldown values are read or reformatted by addon code.
- `ReloadButton.lua` creates a small refresh button anchored to the left of the compact action-bar toggle and reloads the interface on left-click through `C_UI.Reload`, with `ReloadUI` as a fallback. It loads after `GamepadCompactButton.lua` and uses the native minimap rim and refresh artwork.
- `GamepadCompactButton.lua` adds a shortcut below the minimap and toggles `GamepadUseCompactActionBar` outside combat. Native CVar callbacks refresh the action-bar layout; login, CVar, and combat events refresh the icon and tooltip without changing native bar methods.

- `GamepadLeaveGroup.lua` fills the native shortcuts bar's unused bottom-face slot, preserving native shoulder routing without writing native targeting state. The shortcut is invitation-only for a friendly player target; it calls `C_PartyInfo.InviteUnit` with the realm-qualified name, and disables invitations to existing group members. The quick wheel’s reserved bottom slot calls an addon-owned request method after the wheel closes, which rechecks group membership and calls `C_PartyInfo.ConfirmLeaveParty` immediately. No confirmation popup, dialog definition, or popup data is created. It positions an addon-owned prompt at the unused fourth row of the persistent legend's middle shortcuts column, and refreshes availability on roster changes. Protected button setup waits for combat exit; target and roster changes refresh the action. A 0.1-second refresh observes the native bottom-face click handler after button resets or swaps and mirrors the bags row’s visibility. It avoids native setup-method and helper-row show/hide hooks, without inserting into Blizzard’s legend tables or calling its visibility refresh.
- `InstanceChat.lua` uses native chat-window creation and message-group APIs on first world entry to create or reuse the permanent Instance tab and persist party/raid/instance filters. Existing filters are preserved, duplicate groups are skipped, and combat defers setup until combat ends.
- `ChatHistory.lua` snapshots up to 120 non-secret text/color entries per permanent chat frame at logout into character SavedVariables. The first world-entry event restores them only for UI reloads, matching frame and tab names and using native `BackFillMessage` in reverse order within available buffer capacity. It excludes the combat log and closed temporary tabs, discards session-specific message metadata, and consumes the saved snapshot once. Open whispers use native `FCF_OpenTemporaryWindow`, reusing matching existing tabs; Battle.net friends resolve by BattleTag to the current account name. Pending whispers retry on friend-list updates or combat exit and persist across reloads until resolved or a fresh login clears them. Native `inUse` controls closed-tab exclusion. Session-specific Battle.net links are stripped and opaque target tokens are remapped.
- `QuestTracker.lua` reads and stably sorts the full native watch list in a private table, then reorders watches through native remove/add APIs outside combat. Watches are inserted in reverse sorted order because the native API prepends them. Each removed watch is immediately restored, and the super-tracked quest is restored after the batch. Events debounce the work; a secure post-hook on native watch sorting reapplies level order after zone sorting. Verification suppresses repeat attempts for a rejected order. Native tracker methods, quest block data, and click handlers are untouched; native layout handles overflow and special quest priorities.
- `tools/restore-touchpad-config.py` restores left/right touchpad mappings for DualSense and DualSense Edge in the selected client WTF directory, backing up existing configuration and preserving unrelated mappings. `tools/CONTROLLERS.md` documents usage; the tools are excluded from addon packages.
- `AttackMacros.lua` builds spell-rank upgrades from learned, active player spellbook entries using `IsSpellBookItemLowRank`. Each lower rank maps to the unique highest-rank entry with the same name in its skill line; ambiguous names are skipped. Direct spell actions upgrade before macro conversion, and owned macros are edited in place with updated saved bodies and spell IDs. Rank upgrades run independently of the attack-conversion toggle and share its combat, cursor, and temporary-bar guards.
- `MacroRanks.lua` removes explicit ranks from recognized spell operands in character and account macros. `AttackMacros.lua` supplies localized spell/rank names from the learned player spellbook and invokes it under the shared mutation guards, after migrating owned macros to rankless bodies. The parser preserves conditions and reset prefixes, handles sequence delimiters outside brackets and parentheses, and leaves unrelated commands intact. Macro names and icons are preserved.
- `GamepadCamera.lua` checks `IsPlayerMoving` on movement events and every 0.05 seconds after login. It switches the native `GamePadTurnWithCamera` CVar between `2` while moving and `0` when stopped, writing only on changes and restoring `0` at logout. It uses the unrestricted movement boolean rather than restricted unit speed data; native code performs camera-driven turning.
- `AttackMacros.lua` scans persistent keyboard slots and native gamepad storage mappings after login, spell, action, cursor, and combat events. Outside combat it classifies direct spell actions with `C_ActionBar.IsHarmfulAction`, creates rankless character macros, and replaces actions through `PickupMacro`/`PlaceAction`. Generated macros share the display name `+`; character macro scans match saved bodies to spell IDs and migrate legacy names before processing action slots. Body comparisons normalize line endings and trailing newlines, and reuse matches command bodies across spell IDs. Exact generated templates with generated names recover missing ownership. Before conversion, duplicate owned bodies redirect action references across keyboard and all contiguous native gamepad storage (including inactive stances), verify placements, and delete redundant macros in descending index order. Helpful-spell classification uses `C_Spell.IsSpellHelpful` to veto conversion. Existing owned helpful macros restore their stored action references to the highest learned spell rank and are deleted only after successful placement verification, before duplicate consolidation and capacity checks. Failed placements retain the affected macro. Per-character SavedVariables track macro ownership and enablement; restoration checks ownership before picking up the highest learned rank. A debounced event handler avoids synchronous mutation recursion. Controller stance storage is processed as each stance becomes active; temporary action-bar states defer changes.
- `ProfessionTooltip.lua` attaches after the profession UI loads. A driver parented to the crafting schematic form refreshes a dedicated recipe-result tooltip and two native comparison tooltips every 0.2 seconds while visible. It uses the output icon's recipe-result arguments, yields to native hover tooltips, clears stale previews after schematic initialization, and hides its tooltips with the form.
- `ForeverTweaks.toc` declares addon metadata and loads the Lua modules in order.
- `.pkgmeta` defines CurseForge archive layout and exclusions; `LICENSE` supplies the distribution license. Tag packaging replaces the manifest version token and disables alpha-marked diagnostics in beta and release packages.
- At login, `C_CVar.SetCVar` disables `GamepadShowAutoAuraTooltip`. Blizzard then skips its automatic aura-popup queue. No aura data is read or native queue mutated, and manual tooltip inspection remains available. The CVar persists in client settings.
- The same login handler disables `GamePadTouchCursorEnable`, leaving touchpad cursor movement to an external native-mouse mapper. This persistent native setting is separate from device button mappings.
- The same login handler sets `GamePadFactionColor` to `0`.
- The login handler also sets `groundEffectDensity` to `250` through `C_CVar.SetCVar`, including UI reloads.
- The same handler requests `cameraDistanceMaxZoomFactor = 4` without calling camera movement APIs. The native client limits the accepted zoom factor and distance.
- The same login handler requests 60-yard NPC and player nameplate ranges through `nameplateMaxDistance` and `nameplatePlayerMaxDistance`. The client enforces its range limits; these native settings also affect enabled friendly plates.
- The same login handler sets `GamepadDisableTooltips` to `0`, preventing native `GameTooltip_OnShow` from hiding item tooltips in focused controller menus.
- The login handler attempts to set `GamePadOverlapMouseMs` to `0` for mapped mouse movement. This currently does not work: the effective value remains `2000` despite a successful write; the cause is unconfirmed.
- The compact action-bar button combines three texture slots with the day/night indicator’s `UI-HUD-Minimap-Frame-Cycle` rim; hover highlights the circular rim.
- `Reload.tga` supplies the manifest’s addon-list icon.
- `Reload.png` is a PNG copy for sharing and project artwork; it is excluded from the game package.
- A temporary animation driver interpolates a shared combat blend with a 0.45-second cosine ease, driving unit/gamepad opacity from 0.4 to 0.7. Reversed transitions start at the current blend; the driver stops at completion. Login and world entry initialize directly to the current combat state.
- The chat ticker installs one secure post-hook per chat frame on `SmartNavigationCloseHandler`, clearing its edit box after gamepad Back releases focus and covering newly opened tabs. Chat activation and chat/sticky attributes remain under native control because addon writes can taint the subsequent protected gamepad interact-target update.
- Secure post-hooks on native `FocusGamepad` and `UnfocusGamepad` temporarily expand and restore the chat height, resizing the dock primary for docked tabs. The original `CHAT_FRAME_TEXTURES` artwork shows and hides immediately in the focus hooks at native opacity, without animation. Native hover fade post-hooks cancel competing artwork fades and reapply focus visibility; the chat ticker preserves that visibility. The expanded owner is temporarily anchored at its existing bottom-left corner with scale-correct offsets so it grows only upward. Expanded height uses the screen height minus twice the bottom offset in the owner’s scale, preserving the original height as a minimum. Focus exit, hide, and logout restore its original size and all anchors.
- The chat ticker applies `SetTimeVisible(30)` once per chat window, including newly opened windows, without overriding native focus-based fading or scroll behavior.
- The existing chat ticker hides regions listed by Blizzard's `CHAT_FRAME_TEXTURES`, covering new windows and hover backgrounds without calling chat-setting APIs or generating configuration events.
- Focus/show/hide hooks immediately toggle the three native chat input background textures by alpha, with the chat ticker refreshing their state. The same refresh controls channel header, header suffix, and language header alpha, preserving native visibility and width measurements; the gamepad close hook refreshes after clearing the draft. The background follows the input geometry without changing text, focus, or input handling; the three colored focus-border textures are visible during gamepad expansion and transparent otherwise.
- Chat input show/text hooks measure drafts with a hidden font string and extend the native scrollbar-relative right anchor. The chat ticker refreshes header, font, and layout changes; effective-scale conversion caps growth at the screen edge while preserving the native left anchor and minimum width.
- A single login-started 0.1-second ticker scans Blizzard's `CHAT_FRAMES` list and sets each tab's alpha from its hover state or shared dock expansion state, canceling competing native tab fades, matching UITweaks and covering newly created tabs without replacing native chat methods.
- `PlayerFrameXP.lua` displays earned/rested XP as concentric radial arcs using the transparent-center `XPRing.tga` texture, inset six pixels from the level badge bounds to preserve the outer rim. Constant native RadialProgress animations place gold earned XP over a cumulative blue earned-plus-rested arc, capped at one circle. Both textures rotate by half a turn to start at the top and use a narrow nonzero feather where supported. The native level number draws above the ring; the name row remains under Blizzard control. XP, exhaustion, and player-art updates refresh progress and visibility. A container update script masks the original XP artwork and mouse input without hooking bar assignment or animation methods.
- Addon-load and login events hide `PTR_IssueReporter`; an `OnShow` hook keeps the floating panel hidden if the beta UI reopens it.
- A post-hook on `PopFrameAttachedSurvey` hides the separate quest feedback survey, with an `OnShow` hook for subsequent openings. It does not submit feedback or hide the quest frame.
- Combat, login, world-entry, and addon-load events apply 0.4 or 0.7 alpha to `PlayerFrame`, `TargetFrame`, `GamepadMainActionBarFrame`, `PlayerCastingBarFrame`, and `GamepadPlayerCastingBarFrame`. Show hooks reapply the current alpha when these frames reopen; the gamepad parent covers its main and override bars. Guarded cast-bar `SetAlpha` post-hooks scale native opacity writes without compounding them. Native hold/fade animation endpoints use the same combat opacity because animation alpha bypasses `SetAlpha`.
- `AGENTS.md` contains project usage and repository rules; `README.md` is a relative symbolic link to it.

Both buttons follow the minimap's position, scale, and visibility. Protected-action events retain bounded diagnostics in client-managed SavedVariables for investigating blocked quest and menu actions. CurseForge alpha markers gate the entire diagnostic handler, its TOC SavedVariables declaration; beta and release packages leave these inactive.

The controller restore tool also maps raw Share/Create input 4 to `PADBACK` on both DualSense models, supplying native menu actions after the touchpad inputs are reassigned. This stays in device configuration rather than overriding individual menu bindings.


- Protected-action captures record insecure native field names and addon ownership along the Bind/interact path inside alpha-only diagnostics. They do not replace native methods or enable client taint logging.

## Bind-menu taint diagnosis

Opening native item Bind produced `ADDON_ACTION_FORBIDDEN` for `SetPreferredGamepadInteractTarget()`. The captured native path was `BindItem` → `EnterBindingMode` → `SetOverrideAllowLeftRightModifiers` → `AssumeCoreBindingsAreUsable` → `UpdateActionBarFocusedState` → `UpdateInteractIcons`. The failure occurred outside combat on the first open, before opening the wheel picker.

Disabling `GamepadQuickMenu.lua` removed the error. Removing native layout hooks and moving or replacing the hint did not resolve it. Re-enabling the wheel after replacing its protected visibility-proxy children on native panels resolved the Bind error in game.

`DiscoverCombatBlockers` uses `SecureHandlerWrapScript` on each observed panel’s `OnShow` and `OnHide`. These wrappers update `blocker-N` flags on the addon-owned secure owner and run `combat-refresh`; that snippet reads the flags to close the wheel and release Share when native interfaces take priority. Initial visibility and newly available panels are discovered outside combat. No protected proxy children are attached to those panels.

The Quick Menu hint remains an unprotected visual-only child inside the native bottom panel. Its presence is distinct from the removed protected visibility proxies. The exact internal client taint propagation was not established; the isolation and successful replacement identify the problematic quick-wheel integration. This finding does not establish that every protected child elsewhere in the addon causes the same failure.

## Taint troubleshooting limitation

Wrapping a native call in `securecallfunction` does not sanitize already tainted tables, fields, arguments, or callback registrations. It is not a substitute for finding and removing the addon integration that contaminates the native path. Do not infer a successful fix from the wrapper alone.

The former Leave Party confirmation failed in game with both an addon-owned dialog definition and Blizzard’s generic definition. Captures showed `SetPreferredGamepadInteractTarget` failures during popup show/hide, followed by `DescendStop` and `RunBinding` failures. Leave Party bypasses confirmation entirely through `C_PartyInfo.ConfirmLeaveParty`, removing that popup/controller-focus integration. In-game validation of direct leaving is pending.


Quick-menu source/alpha diagnostics retain the last 20 distinct routing snapshots in `ForeverTweaksDiagnostics.quickMenuRouting`. The polling capture records initialization, effective Share binding, focus and binding-stack gates, visible/secure blockers, and mapped pressed buttons without native hooks or chat output. The capture uses `C_GamePad.IsEnabled` in ordinary Lua and runs behind `pcall` after binding refresh so diagnostic errors cannot interrupt routing. Beta and release packaging removes the capture and its polling call.
